# 二楼分层 PNG 资产

门资产后续修订：正式三态门使用用户最初的 201 门型，见 [五门三态说明](../doors/rooms_201_205.md)。本目录五张单态门仅保留作历史分层参考，不作为三态门替代品。

仅二楼环境，不含角色。保存于 `assets/final/floor_2_layers/`，使用现有 `work/member-C-yinshiqi` 分支。

**这套资产由用户的平面 PNG 参考提取、AI 重建后分格导出，并非原始 PSD 图层的无损恢复。** 家具雕花、门框比例及部分细节与原图存在差异；被遮挡的墙面、楼梯和柜体边缘需要补绘。`reference_only/` 是原图原始像素的三块分区参考，不是干净背景层。没有把整栋楼缩成一张图再放大。

## 组合与导入

- 前后顺序按目录编号；人物由游戏自身绘制在交互物件前、前景遮挡层后。角色未在本包中制作。
- 透明物件均保留 **512×512** 格子画布，不分别自动裁边、不按透明内容边界自动缩放。`manifest.json` 给出每张图的尺寸、alpha、建议锚点、来源和 SHA-256。
- 门采用一致的格子和相同美术缩放；建议底部中心锚点 `(256,512)`。Sprite2D 可设 `centered=false`、局部位置 `(-256,-512)`，缩放统一放在父节点。挂画可改用中心锚点，光效建议中心 `(256,256)`。
- 这些透明边距是导出格子的一部分，物件实际底边不一定等于格子底边。摆放时按可见接触点校准一次，并保留该配置；不能把“同一格子”当作已经精确对齐源图全部物件。
- 墙面模块 1774×887，地面模块 2172×425，远景模块 1536×1024。用小模块多次组合，避免先将整层走廊压缩成小图再放大。相邻模块可交替水平镜像，使相邻边缘接续；普通单向 repeat 的图案周期未保证无缝。先按目标世界高度等比缩小，再决定重复次数，不非等比拉伸。
- Godot 使用无损纹理导入、`size_limit=0`、不生成 mipmaps、保留 alpha；描述文件随 PNG 提交，`.godot/` 缓存不提交。没有改动正式楼层实例或 `project.godot`。
- 204 的门本体与顶端警报灯／射线分开；205 为原参考中的开门造型。灯泡、门内局部照明及物件自身明暗仍有烘焙像素，外部光晕和接触阴影可独立控制；这不是完整的无光照材质拆分。
- 原有 `assets/final/doors/room_201/` 三状态门保持不变。本包的五扇门是**单状态静态图**，不能替代原有门状态动画集。

原图没有可独立识别的污渍、登记台、正式出口牌，也没有可拆出的角色；本次不虚构这些资产。楼梯入口是图中可见的通行模块，包裹柜内原有小物件仍画在柜体上，另提供一个独立信封。

## 验证与来源

- 内置 imagegen 编辑与真实 alpha 输出，随后按用户要求将资产层图集无损分割为独立 PNG；没有使用生成 API／CLI fallback。
- 棋盘底预览逐张检查透明边缘、房号 201—205、五门格子尺寸及效果层；PNG 解码、alpha 和 SHA-256 校验，源图三区逐像素核对。
- 提示词规格见 `prompts.md`。`manifest.json` 中 `ai_*` 和 `source_pixels_unchanged` 明确区分重建与原像素参考。
- 本次交付只提供资产，没有替换主线当前背景或完成交互组件接线；不会把 PNG 的绘画内容当作游戏功能已实现。
