## 如何打开当前项目

1. 用 GitHub Desktop 克隆共同仓库；已有本地副本时先检查并保留自己的未提交修改。
2. 打开 Godot 项目管理器，选择“导入”，定位到仓库中的 `project.godot`。
3. 进入编辑器后核对 Godot 版本为 4.7.2。首次资源导入产生的 `.godot/` 缓存由本机生成，不提交。
4. A 分支按 F5 运行 `scenes/main.tscn`，点击“开始游戏”后 E／鼠标继续真实序章；结束后 A/D 行走，到 1F x2400 的经理附近按 E 交谈，再去右端楼梯 E 上 2F。以上为 A 当前工作区；共享 main 尚不含本轮 UI／检查点整合。Mac 可双击 `.tscn` 后按 Command+R 运行当前场景。
5. F6 运行当前测试场景。各成员的入口见 [组员接入说明](docs/onboarding.md)。

F5 到 201 后点击“接受任务”才开始 210 秒计时；关闭面板不会接受，门前按 E 可重开。回 1F 等保洁的好奇状态结束，绕后长按 E 0.8 秒取得工作证；回 2F 用 Q 确认当前为保洁身份，在污渍处按住 E 1.5 秒，再回 201 按 E 交付。被抓／超时点“重新挑战本任务”，恢复接取前状态并重新接受；失败页“返回菜单”回到主菜单，点击开始会清空本局并重播序章。I 查看／装备实际卡片，H 查看操作和调查笔记，页面期间停表。经理后只有两条模糊线索，201 交付才揭示长鼻规则。普通门违规只警告退回来侧。

F6 运行 `scenes/tests/core/task_01_core_test.tscn` 可检查当前 A 侧任务循环（**开发入口，不是正式 UI 验收**）：

1. 点“代记经理对白”，走到 1F 右端按 E 上 2F；到 201 会由真实门发出介绍，再点“开发：接受任务”。
2. 返回左端楼梯下 1F；保洁发现陌生人时会短暂显示 `? / CURIOUS` 并朝向玩家，这本身不判失败。等好奇结束、观察实际朝向再绕到身后，按住 E 0.8 秒取得卡；正面按 E 仍会被抓。当前任务不允许偷保安／经理卡。
3. 回 2F，确认当前卡为 CLEANER（Q 切换），到污渍 x980 按住 E 1.5 秒；再回 201 按 E 交付，才解除 x1250 路障。已移除代记清洁／交付按钮。
4. 正面偷卡／偷窃中被转身发现，或用开发按钮模拟超时，会进入真实任务失败。点“开发：检查点重试”回 2F x560，撤销本任务卡／清理结果，保留接取前成果；重新接受才从 210 秒开始。

## 协作流程

每次开始先检查当前分支和修改清单、保留已有工作，再同步已发布的最新 main。在自己的模块和独立测试场景开发；完成后写清改动、实际测试和 A 需要接入的位置，再提交 PR。A 每接入一个模块就回归已有功能，main 只接收可运行的版本。

跨模块修改先明确范围和接口；不得通过复制卡片数据、另建管理器或重写他人模块绕过接入问题。当前按编号逐项推进，具体任务见 [执行清单](PLANS.md)。
