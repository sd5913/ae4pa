# 怪物员工通道 Monster Staff Access

四人协作的单人 2D 横向潜行解谜游戏。V4 目标是：探索五层怪物旅馆，被剧情怪物拦下后接限时任务，逐步取得员工身份、完成工作并交付解锁，在三楼 309 救出闺蜜，办好离店手续后从五楼逃离。

**V4 文档已获用户确认，当前游戏代码仍为旧玩法基线。** 共享 main 的 F5 入口仍是公共测试走廊；以下 A-05 状态指 A 的本地未提交版本，本次只上传文档。 当前本地 A-05 主入口可进入 1F，从三名员工身后长按 E 获得三张 ID，集齐后到右端按 E 上 2F，卡片与装备保留。已有五层占位与独立换层预览；房门、救援、重试及正式 UI 尚未接入，完整主线尚未完成。已完成的工作和验证证据见 [进度记录](docs/progress.md)。

团队先读 [项目主策划 V4.0](docs/game-design.md) 和 [ABCD 分工 2.0](docs/team-plan.md)。[V4 改造与审阅说明](docs/v4-migration.md)列明新旧差异、来源页码和待确认衔接。排期按里程碑推进，日期待定；先完成 201 清洁任务的完整成功／失败／重试循环。

## V4 目标范围（尚未实现）

- 仍是五层、三卡双槽、五怪、309 救援和五楼逃脱，主角只左右移动。
- 1F 经理对话后可上楼；保洁、保安、经理卡随任务取得，并用于清理、取件和批准。
- 单个限时任务接受后计时；对白、手册、背包和暂停停表，楼梯支持合法回访。
- 剧情任务完成才开通路；普通门违规警告并退回安全点；被员工发现或超时恢复任务检查点。
- 三卡背包不扩展为通用物品背包；任务文件只记录状态。不开战斗、跳跃、追逐或客房内部。

详细行为、五任务流程和仍待审阅的建议见主策划。下面的运行方式描述当前代码，不代表 V4 已可玩。

## 如何打开当前项目

1. 用 GitHub Desktop 克隆共同仓库；已有本地副本时先检查并保留自己的未提交修改。
2. 打开 Godot 项目管理器，选择“导入”，定位到仓库中的 `project.godot`。
3. 进入编辑器后核对 Godot 版本为 4.7.2。首次资源导入产生的 `.godot/` 缓存由本机生成，不提交。
4. 运行 `scenes/main.tscn`：共享 main 进入公共测试走廊，可检查 A/D 移动和临时状态显示。B 员工和 C 门分别在独立 F6 场景验证；五层占位看 `scenes/tests/core/floors_test.tscn`。Mac 可双击 `.tscn` 后按 Command+R 运行当前场景；F5／运行项目使用默认入口。
5. F6 运行当前测试场景。各成员的入口见 [组员接入说明](docs/onboarding.md)。

A 本地未提交 A-05 版本的额外行为：1F 从员工背后长按 E 约 0.8 秒取得三卡，集齐到右端 E 上 2F；这些代码不随本次文档发布。查看五层：打开 `scenes/tests/core/floors_test.tscn` 按 F6（Mac 默认 Command+R）。1F 同样可实际偷卡；顶部“开发：下一层（跳过条件）”仍可用于查看后续层，但不算正式通行。“开发：新局（重新偷卡）”回到 1F 并清空卡片，不是本层重试。当前获得／朝向／失败提示和双槽显示均为 A 的临时开发显示，等待 D 正式 UI 替换。B 的正面偷卡暂时只拒绝，按用户决定等待 B 后续迭代；当前按回头失败测试失败反馈。

不要为个人功能另建一套 Godot 项目。运行入口和验证方法随底座完成更新到本文件。

## 协作流程

每次开始先检查当前分支和修改清单、保留已有工作，再同步已发布的最新 main。在自己的模块和独立测试场景开发；完成后写清改动、实际测试和 A 需要接入的位置，再提交 PR。A 每接入一个模块就回归已有功能，main 只接收可运行的版本。

跨模块修改先明确范围和接口；不得通过复制卡片数据、另建管理器或重写他人模块绕过接入问题。当前按编号逐项推进，具体任务见 [执行清单](PLANS.md)。
