## 核心玩法

单人、纯 2D、五层横向怪物旅馆。主角在 1F 从三名工作人员背后偷取保安、保洁、经理 ID；在 2F—5F 观察定时开门的怪物并按规则通过；3F 的 309 房救出闺蜜，5F EXIT 逃脱。

全程循环：观察门和预警 → 在安全区域选择身份或等待 → 通过检测区 → 到达目标并交互。人物只沿水平线移动，松开按键立即停止。

不制作跳跃、战斗、血条、追逐与寻路 AI、进入客房、复杂机关、多人联网、随机地图或分支结局。美术先用占位素材，不阻塞功能开发。

## 卡片与工作人员

- 三卡固定标识为 `SECURITY`、`CLEANER`、`MANAGER`；不增加仓库卡、技能或开门权限。
- 已获得的卡保存在卡片管理器；最多佩戴两张，当前只有一张生效，第三张留在背包。
- 第一张进入槽 A，第二张进入槽 B，第三张留在背包；不丢弃、不重复获得。
- 工作人员固定站位、定时转向；在背后且距离不超过约 55 像素时，按住 E 约 0.8 秒偷卡。
- 偷卡时站定；在正面尝试偷卡或偷取过程中被回头看到，失败原因为 `STAFF_CAUGHT`。
- 1F 集齐三张卡后才能上 2F；1F 重试要重新偷卡。

## 共用房门与五种怪物

所有怪物复用同一房门组件。只有门为 OPEN 且主角在水平检测范围内时，才检查怪物规则。CLOSED 和 WARNING 不触发怪物失败。

| 标识 | 怪物 | 开门且在检测区内时的失败条件 |
|---|---|---|
| `EYE` | 独眼客 | 当前卡不是 `SECURITY` |
| `NOSE` | 长鼻客 | 当前卡不是 `CLEANER` |
| `HAT` | 礼帽客 | 当前卡不是 `MANAGER` |
| `EAR` | 大耳客 | 主角仍在移动，卡片无保护作用 |
| `CHECKER` | 核验客 | 发生 Q 切卡或背包装备替换；单纯行走安全 |

房门按 CLOSED → WARNING → OPEN → CLOSED 循环。原型起点：关闭 5.5 秒、预警 1.4 秒、开启 2.8 秒、检测半径 90 像素。数值可调，不是不可更改的最终平衡值。

预警必须可见，静音仍能理解；怪物也应能从形状和图标辨认。首次版本用固定门序和固定相位，随机相位放在主流程可玩后。相邻检测区之间建议至少留 120 像素安全空间，并实际验证能后退和等待。

## 楼层与故事

| 楼层 | 正式游戏内容 |
|---|---|
| 1F | 保安、保洁、经理三名工作人员；没有怪物；三卡集齐解锁上楼 |
| 2F | 201 EYE、202 NOSE、203 EAR、204 HAT、205 CHECKER |
| 3F | 301 NOSE、302 EYE、303 CHECKER、304 HAT、305 EAR；309 救援 |
| 4F | 401 EAR、402 EYE、403 HAT、404 CHECKER、405 NOSE |
| 5F | 501 HAT、502 NOSE、503 CHECKER、504 EYE、505 EAR；EXIT 通关 |

救援后设置 `has_friend = true`。闺蜜只作跟随显示，不独立碰撞、寻路或参与怪物检测。楼层切换可用淡入淡出，无需楼梯或电梯动画。

周末小样可用专门的测试走廊同时放保安与独眼门；该测试走廊不替代正式 1F 的设定。

## 失败与重试

统一失败原因：`STAFF_CAUGHT`、`WRONG_CARD`、`MOVED_NEAR_EAR`、`SWITCHED_NEAR_CHECKER`。界面必须说明原因，并提供重试本层。

失败后回当前楼层入口，重新设置房门计时。1F 清空本轮卡片获取重新偷；2F—5F 不丢失三张卡，已完成的救援进度应按最终接口规则恢复。

策划案同时写了“入口记录装备快照”和“保留救人状态”。3F 本层救人后的失败、是否恢复当前装备或入口装备，在重试与救援功能开发时统一决定，不由各模块自行定义，也不阻塞当前底座工作。
