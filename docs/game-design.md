## 1 游戏定位与边界

女主收到闺蜜从三楼 309 发来的求救消息，潜入五层怪物旅馆。玩家先带着不完整情报探索，被剧情怪物拦下后接限时任务，为任务偷取员工身份、完成工作，再交付解锁通路；救出闺蜜后完成离店手续，从五楼消防门逃脱。

核心循环：**观察 → 剧情拦截 → 接受任务 → 获取身份／文件 → 完成工作 → 返回交付或授权结算 → 解锁通路与线索。** 普通房门在任务之间提供观察、等待、停步和提前换卡的玩法。

| 保留的规模 | V4 新增的联系 |
|---|---|
| 五层纯 2D 横向走廊，只左右移动 | 可通过楼梯回访已到达且当前允许访问的楼层 |
| 三张工作证、两个佩戴槽、当前一张生效 | 工作证同时提供怪物伪装和工作权限，按任务逐步获得 |
| 五种怪物、一套三状态门 | 区分剧情任务拦截与普通门违规退回 |
| 人类员工固定站位、周期转身、背后偷窃 | 同一偷窃过程可取得卡或任务文件 |
| 309 救援、闺蜜跟随、五楼逃脱 | 五项限时任务把身份、工作和剧情串起来 |

不制作战斗、血条、攻击、跳跃、上下自由移动、攀爬、怪物追逐／寻路、客房内部、物理搬运、复杂清洁小游戏、通用物品背包、升级商店、Boss、第六怪、多结局、随机地图或联网。大耳客可选取物任务不纳入本轮五任务范围。

技术沿用 Godot 4.7.2 标准版、GDScript、Compatibility、1280×720。优先占位图和小场景，不因 V4 引入通用任务框架或新插件。

## 2 当前游戏与目标的区别

截至本轮只读核对，本地 A 分支保留未提交的 A-05 接入：主入口有 1F 三员工、长按偷卡和集齐三卡后上 2F；五层仍是占位／预览。B 的卡片与员工可复用，C 的五怪、offset 与多门测试已在源码中；C 门尚未组装进主流程，D 正式 UI 尚未交付。

当前没有任务倒计时、任务检查点、楼层回访、工作交互、普通门退回、309 救援或通关实现。现有测试通过记录只证明当时旧行为，不能直接作为 V4 验收。本轮只修订文档，不改游戏脚本、场景和项目设置。

## 3 故事与信息揭示

### 3.1 开场：手机消息、回忆、前往旅馆

源案建议 2—3 分钟视觉小说式开场，静态背景、手机界面、立绘、底部对白即可。E／鼠标继续，已观看内容可跳过；首次是否也允许整段跳过为整合建议，见 D-01 决策。

1. 深夜手机收到：“你能来接我吗？”“他们不让我离开。”“我在三楼，309 号房。”“别相信这里的工作人员。”消息停止，电话无人接听。
2. 回忆数日前闺蜜拿到夜班兼职录取：工资高、不需经验；女主担忧。通知角落出现“员工离店须经管理部门批准”，只作伏笔。
3. 回到现实，女主拿外套赶往夜班旅馆，明确目标“先找到上楼的办法，去 309 找她”。出现游戏标题后进入可操作 1F。

不增加配音要求、逐帧动画、分支对话或额外剧情地图。

### 3.2 1F 经理对话

玩家主动走到前台按 E 询问。对白必须涵盖：闺蜜夜班失联、309 是客房区、经理回避真相、住客有自己的规矩、“有的客人不喜欢陌生人，有的对气味很敏感”“出了问题，记得找工作人员”。

对话结束后开放 2F，解锁 H 调查笔记，仅给两条模糊线索：

- 有些住客不喜欢陌生人。
- 有些住客对气味敏感。

**取消“一楼必须偷齐三卡才能上楼”**。保洁工作区、前台经理、保安值班台保留作为环境铺垫；1F 保安台不再提供第二张保安卡，保安卡来源在 2F 员工值班点。

### 3.3 救援与结局

任务 03 解除登记限制后，309 按 E 播放救援对白，不进入客房内部。对白说明临时兼职被登记为长期合同、女主已解锁登记、三楼以下员工通道被封，五楼消防通道是出路。对白完成才记为已救援并开放 4F。

闺蜜跟在主角身后固定距离，原型可沿用约 40 像素；不独立碰撞、寻路、被抓或触发怪物。换层、任务重试后按故事状态重建显示。

任务 05 完成后抵达 EXIT，按 E 淡出到旅馆外景。结尾保留“我们……真的出来了？”“以后别再找这种奇怪的兼职了。”“我发誓。”显示 ESCAPED!、重新开始／返回菜单。总时长、被发现次数、完成任务数是后期统计展示，不阻塞首个闭环。

## 4 操作、暂停与交互

| 动作 | 按键 | V4 目标行为 |
|---|---|---|
| `move_left`／`move_right` | A/D 或左右箭头 | 水平移动，松手停止 |
| `interact` | E | 谈话、接近目标后的取物／交付／批准、楼梯、救援、出口；偷窃与清洁使用长按 |
| `switch_id` | Q | 切两个佩戴槽中的当前槽，由 B 的单一入口执行 |
| `open_bag` | I | 三卡背包，替换佩戴槽 |
| `open_help` | H | 操作说明与逐步解锁的调查笔记 |
| `pause` | Esc | 暂停、继续、返回菜单；重试入口按任务状态显示 |

源案明确：任务对话、手册、背包和暂停期间**停止任务倒计时**。任务面板明确展示“接受”后才开始计时；仅触发对白或看面板不开始计时。

整合建议 D-02：这些模态页面同时冻结玩家移动、员工转身和门周期；关闭后从原进度继续。背包内仍可调整卡片，但核验客是否判定这次换装不能被暂停吞掉：按打开背包前保留的门状态、主角位置判断，关闭页面前处理警告退回；只开背包不算违规。具体显示顺序在 V4-01 确认。

整合建议：同一时间只显示一个可操作的世界 E 目标。A 选择目标，B/C/D 提供行为；UI 打开时 UI 优先消费输入，关闭／确认后要求松开 E 再触发下一次世界交互，避免一键既关闭对白又偷窃或上楼。候选目标优先级和取消规则见 [接口 V4 提案](interfaces.md#13-v4-目标接口提案尚未实现)。

## 5 工作证、偷窃与工作权限

### 5.1 三张 ID 与双槽

| 卡片 | 现有 ID | 来源和首次教学 | 怪物伪装 | 工作权限 |
|---|---|---|---|---|
| 保洁（绿） | CLEANER | 任务 01，回 1F 保洁区偷取 | 长鼻客 | 清理污渍 |
| 保安（蓝） | SECURITY | 任务 02，2F 中段保安点偷取 | 独眼客 | 保管柜领取包裹 |
| 经理（紫） | MANAGER | 任务 03，回 1F 前台偷取 | 礼帽客 | 批准 309 登记及离店单 |

沿用现有第一张入槽 A、第二张入槽 B、第三张留背包；不自动改变玩家当前槽。任务 01 教取得并使用保洁，任务 02 教 Q 切保安，任务 03 教 I 替换槽并切到经理。工作权限判断使用**当前生效卡**，只拥有或放在备用槽不算授权。

不丢弃、不消耗、不重复收集；最多两槽，当前一张。任务中的新卡在正常游玩中保留，但失败回滚会撤销本次任务中取得的卡，前面完成任务获得的卡不会丢失。这是源案第 9 节检查点对“永久拥有”的明确例外。

核验客检测 Q 和成功装备变更，包括备用槽替换；普通刷新与重复无效操作不算换装。空槽／卸下行为暂按 B 当前事实记录，最终玩家规则在 D-06 确认。背包只是卡片显示和请求，不另存所有权。

### 5.2 人类员工偷窃

员工固定位置、左右转身，不巡逻。保留靠近、在背后站定、长按 E 约 0.8 秒；距离起点约 55 像素。转身预告沿用旧目标约 0.4 秒，转向间隔先用现有配置，再试玩调整。

源案明确：正面尝试偷窃或中途被回头发现，任务失败；成功才授予卡或文件，不能重复取得。当前代码正面只拒绝，B 必须在新阶段修正。

整合建议 D-01：按任务解锁可偷目标，避免任务 01 前偷齐三卡；经理前台谈话与偷卡分别按剧情状态、站位选择。任务 04 的巡房表复用同一背后／朝向／长按逻辑，只把奖励从卡片改为文件状态；不复制第二套偷窃脚本。

整合建议：松开 E、移出范围、尝试移动、切换身份或打开模态页面均取消当前长按并清零进度，任务计时按暂停策略处理；已完成步骤不会因此撤销。中途被看见仍优先作为失败，不能被取消掩盖。

### 5.3 三种工作交互

| 类型 | 条件 | 操作 | 成功结果 |
|---|---|---|---|
| CLEAN | 任务进行中，当前 CLEANER，污渍未清理 | 靠近长按 E 约 1.5 秒 | 污渍显示改变，记录已清理，提示返回 201 交付 |
| PICKUP | 任务进行中，任务 02 要求当前 SECURITY，包裹未取得 | 靠近保管柜按 E | 包裹隐藏，任务物品标记为已取得 |
| AUTHORIZE | 对应任务进行中，当前 MANAGER | 靠近登记台按 E | 309 登记或离店单变为已批准 |

取得／交付文件以布尔或任务步骤记录，不加入三卡背包，不制作拖拽、重量或物理搬运。交付动作单独验证任务和物品／步骤；“捡到包裹”“清理完成”“批准离店单”不等于已经交付。

工作条件不足时给出缺少身份／步骤提示，不消耗卡片、不更新任务；远处按 E 无效果。每个点有固定 ID，回来时按真实状态显示，不能换层后重新生成可重复领取的物品。

## 6 房门与五怪

### 6.1 保留检测，改变后果

| 怪物 | ID | OPEN 且在水平范围内的违规条件 | 普通应对 |
|---|---|---|---|
| 独眼客 | EYE | 当前不是 SECURITY | 保安身份或等待关闭 |
| 长鼻客 | NOSE | 当前不是 CLEANER | 保洁身份或等待关闭 |
| 礼帽客 | HAT | 当前不是 MANAGER | 经理身份或等待关闭 |
| 大耳客 | EAR | 主角发生实际水平位移 | 停步等门关，卡片不保护 |
| 核验客 | CHECKER | 主动 Q 或成功装备替换 | 提前选卡，门前不换装 |

沿用 CLOSED → WARNING → OPEN。V4 建议初值约 5／1.5／3 秒；当前代码为 5.5／1.4／2.8 秒。C 将参数作为试玩起点，不能把文档数值写成已改代码。半径先沿用 90 像素，门相位错开且周期固定，出生点和退回点不能落在危险区。

预警同时有颜色／闪烁及文字或图形，静音也清楚；五怪不能只靠颜色区分。门间必须有等待／换卡空间，具体坐标由 A 摆放、C 验证，不机械沿用旧五门坐标。

### 6.2 普通门

违反规则 → 显示对应警告 → 退到该门**玩家来向一侧**的安全点 → 可再次观察通过。普通门违规不回滚任务、不清空卡片，不直接进入旧整层 FAILED。

整合建议 D-03：退回瞬间冻结移动和检测，落点确认在全部危险区与剧情拦截区之外，再恢复；避免每帧连退、隔门连锁或从回程被传到错误一侧。警告本身不重置任务剩余时间，恢复游玩后继续计时；警告展示期间是否冻结世界按同一模态策略执行，不增加另一个计时器。

### 6.3 剧情任务门

首次到达固定触发点即拦截，与门当时是否 OPEN 无关。先播放对白、展示任务，确认后才计时；不会先按普通规则惩罚一次再接任务。同一时间只运行一项限时任务，正在进行时重复触发只显示当前目标。

**对话放行与任务通关解锁是两件事**：接受后必须能走到所需员工／工作点，但后续剧情区的路障仍锁着；完成任务才永久解除该限制。不能等关门、换对卡或用楼梯菜单跳过关键任务。

整合建议 D-04：接任务后，该任务门允许往返工作路线，不再对玩家重复普通惩罚；任务完成后保留放行与复看对白入口。非任务门仍正常计时检测。此方案具体化 PDF“接受任务后放行”，须审阅确认。

## 7 单任务、倒计时与检查点

### 7.1 生命周期

整合建议状态：未开放 → 可接取 → 进行中 → 可交付 → 已完成；进行中／可交付可转任务失败。任务 03 采用批准即结算的例外，见 D-05。

1. A 检查前置任务、楼层与剧情是否满足，C 请求剧情拦截，D 显示任务说明。
2. 显示名称、目标地点、所需身份、步骤和时限。玩家未接受时可以看说明，倒计时保持未启动。
3. 接受时保存“接任务前”的深拷贝检查点，再启动一个倒计时；不能在偷到卡之后才保存。
4. 工作点／偷窃提交进度事件，A 校验任务及顺序、记录状态，D 刷新 HUD。
5. 返回目标交付并校验完成条件，或任务 03 在登记台批准完成；只结算一次，停止计时，解锁通路／笔记。
6. 倒计时归零或偷窃被发现时进入任务失败，锁世界输入，显示具体原因与“重新挑战本任务”。
7. 重试恢复接取前状态，回到原接取楼层安全点，重新确认接受后从完整时限开始；重复点击不能创建多个任务或计时器。

每任务建议时限：01 为 210 秒、02 为 180 秒、03 为 240 秒、04 为 180 秒、05 为 180 秒。它们是首轮试玩值；至少两名组员分别试玩每项任务，记录路线、暂停外耗时、错误与余量，再调整到熟悉路线正常完成用时的约两倍或更宽裕。

### 7.2 检查点的范围

| 保存内容 | 所有者／恢复要求 |
|---|---|
| 接任务楼层、接取安全位置、可访问楼层与通路 | A；失败发生在 1F 也可回到 2F 的任务接取点 |
| 已有三卡、两槽、当前槽 | B 提供导出／恢复快照，A 协调；不能经 collect/equip 重放产生换装事件 |
| 已完成任务、剧情标记、经理初次对话、309 救援 | A；不删除前面任务成果 |
| 清理、包裹、巡房表、两种批准文件状态 | A 保存任务／世界事实，B 组件按它们重建 |
| 已解锁笔记、楼梯限制和任务门放行 | A 保存事实，C/D 读取；不单靠场景节点 visible 保存 |
| 当前任务和计时 | 重试回接取前，无活动任务；重新接受时用完整配置时限 |

例一：任务 01 先偷保洁、未交付就超时，重试撤销本次保洁卡和清洁状态。例二：任务 02 偷到保安被抓，重试保留任务 01 的保洁卡、201 放行和笔记，撤销保安与包裹。例三：任务 04 失败，三卡、309 已救援、闺蜜跟随都保留，巡房表恢复可偷。

恢复顺序建议：进入恢复状态并关 UI → 取消长按／旧连接 → 恢复 A/B 数据且不产生主动换装事件 → 重载接取楼层 → 应用物件和门／路障状态 → 放置主角／闺蜜／相机 → 同步 UI → 回可接取。门周期恢复配置相位，安全点必须不危险；不用保存每门毫秒相位。

首版只做会话内检查点，不做退出程序后的磁盘存档、云存档或账户系统。无活动任务的偷窃失败如何恢复，随 D-01 的提前偷卡规则确认，不能静默套用旧“1F 清空／其他层入口”。

## 8 五层布局与完整任务流程

### 8.1 路线总览

| 楼层 | 房号／事件顺序 | 上行条件 |
|---|---|---|

### 8.2 任务 01：打扫走廊

| 项目 | 规定 |

4. 成功后保洁入第一槽；正面或中途回头按任务失败处理。
5. 从楼梯回 2F，当前保洁身份在污渍处长按 E，完成后提示“回 201 交付”。
6. 交付成功才解除路障并停表；清理本身不提前解锁下一任务。

布局要求：回楼梯的路线始终可退；污渍位于可达的工作侧，拦住下一段的限制在工作点之后。重复清理／交付不重复奖励。
