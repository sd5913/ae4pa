## 1 每个人负责什么

| 成员 | 原职责继续保留 | V4 新增职责 | 专属文件范围 |
|---|---|---|---|
| A 组长／整合 | Player、主场景、楼层、救援、结局、导出 | 单任务状态、计时、检查点、回访、通路锁、E 目标分发、持久世界状态 | `project.godot`、`scenes/main.*`、`scenes/player/`、`scenes/levels/`、`scripts/game_manager.gd`、拟新增 `scripts/task_definitions.gd`、`scenes/tests/core/` |

| D UI／剧情／测试 | 菜单、HUD、背包、对白、失败／结局、QA | 手机与回忆、经理对话、接任务面板、倒计时显示、调查笔记、楼梯列表、任务重试 UI | `scenes/ui/`、`scenes/tests/ui/`、`docs/qa.md`、玩法说明与交付材料 |

拟新增文件／目录仅是交付位置，当前不代表已创建代码。四人共同选美术，谁使用谁导入；不安排任何人只做图片。

### 数据与跨模块边界

- A 保存任务／故事／通路／物品状态，B 保存卡片状态。A 的检查点可包含 B 导出的副本，恢复必须通过 B 接口。
- B 执行世界工作动作，向 A 报告结果；C 检查规则，向 A 请求拦截／退回；D 显示和发请求。三者不直接改 A 的任务状态或写另一份倒计时。
- C 负责“何时违规、哪扇门、从哪侧接近”的证据；A 负责中断交互、锁输入、移动主角到已验证安全点、恢复游戏。A 放置安全点，C 复核范围，D 显示原因。
- D 的面板只发送接受／重试／楼层选择请求；A 校验条件后执行。所有人不得用读取 UI 文案判断任务步骤。
- 主场景和项目设置只有 A 编辑。B/C/D 提交组件及 F6 场景，由 A 组装，不把组件逻辑复制进 main。
- B 扩展 `scenes/work/` 属于本版建议的最小归属调整；A 只在楼层引用它，不代写 B 的实现。

## 4 A：任务、检查点、楼层与整合

### A-V4-01 核对差异并冻结首个闭环接口（M0）

依赖：本稿审阅；文件：公共文档，暂不改成员代码。

1. 与 B/C/D 核对 `interfaces.md` 的“当前实现”和“V4 提案”，确认各自新增方法、事件、数据所有者。
2. 优先确认提前偷卡、任务门工作路线、模态换装核验、退回点、重试回接取前等 M1 决策；后段决策标出最晚里程碑。
3. 固定 TASK_01—05、工作点、路障、剧情／笔记 ID；保留现有三卡大写 ID 与 `has_friend`。
4. 写出 201 的最小场景路线图／对象清单、输入归属和一条完整调用链，给 B/C/D 相同版本。

交付：可实施的最小接口、决策记录和任务 01 布局草案。验收：成员能说清谁保存数据、谁发事件、谁恢复状态，没有依赖不存在方法的可点击正式按钮。

### A-V4-02 单任务进度与倒计时（M1）

依赖：A-V4-01；文件：GameManager、轻量任务定义、core 独立测试。

1. 先只定义任务 01 的前置、时限、所需步骤和结算条件，避免先搭通用任务编辑器。
2. 实现可接取、接受、进行、可交付、完成、失败；第二个任务不能覆盖活动任务。
3. 接受才计时；暂停／对白／背包／笔记停止扣时，UI 仅读取剩余时间。
4. 校验工作事件的任务、来源、身份和顺序；清洁完成只变为可交付，201 交付才停表解锁。
5. 去重接受／进度／完成／失败；确定超时与交付同帧的统一顺序，写入接口与 QA。

交付：可用的任务读取和操作入口。验收：未接受不扣时、错误事件不推进、重复输入无双重结算、超时原因明确。

### A-V4-03 楼层往返与世界状态（M1，M2 补全）

依赖：A-V4-02、B 卡数据接口；文件：GameManager、floor、楼梯接入。

1. 把 1F 上楼条件从三卡改成经理对白完成；2F 条件改为任务 01／02 完成。
2. 分开记录“已到达”“当前可访问”“下一层解锁”；楼梯请求不能直接任意传楼层数字绕过条件。
3. 加入 1F↔2F，M2 再补 3F 回 1F；在目标楼梯安全点出生，更新相机并绑定组件。
4. 换层前后保留活动任务、剩余时间、卡片、已偷员工／物品、清理与路障状态；不能在 `_ready` 中重置这些事实。
5. 加载过程锁输入／检测，完成重建再恢复；UI 楼层列表由真实允许目标生成。

交付：正式楼梯流程；开发预览继续明确标识。验收：回访不重生卡／包裹、不重置倒计时、不能访问未知层或跳过任务；源场景连接释放。

### A-V4-04 任务检查点与恢复（M1）

依赖：A-V4-02—03、B-V4-02 卡片快照。

1. 在接受前保存接取楼层／安全位置、卡片副本、任务／故事／物品／笔记／访问限制。
2. 统一超时和员工被抓到当前任务失败；普通门警告不走这条链。
3. 重试先关模态 UI、取消长按和旧事件，再恢复卡片／世界状态，重载接取楼层。
4. 恢复主角、门相位、物品、相机和闺蜜，最后回到可接取，等待重新接受；不得偷偷自动开始计时。
5. 验证后续任务失败保留之前成果；重试、换层、新局三种重置不能混用。

交付：任务重试入口与安全恢复顺序。验收：任务 01 在 1F 被抓仍回 2F 接取点；保洁和污渍撤销；任务 02 重试保留已交付任务 01；连续重试不重复连接。

### A-V4-05 E 输入、201 布局与首轮接入（M1）

依赖：B/C 的最小组件、D 基础 UI。

1. 由 A 的当前楼层协调一个世界交互目标，避开经理谈话／偷卡、工作点／楼梯和门交付的输入重叠。
2. 按新布局摆 1F 保洁和经理、2F 201／污渍／楼梯／工作区／路障；先接 B，再 C，最后 D。
3. 安排左右安全点、退路和暂停边界；任务需求点放在可达侧，不能“先解锁才能拿解锁物品”。
4. 连接剧情请求、任务接受、进度、交付、普通警告、失败、重试；移除对应临时假按钮。
5. 跑一次成功、一次被抓、一次超时和一次普通门退回，再回归 Player／CardManager／门原有行为。

交付：一个真实可玩的 201 闭环。验收：从菜单无卡上 2F 到交付均用正式 E 和 UI；不依赖开发跳层或直接改管理器数据。

### A-V4-06 任务 02／03、309 与救援限制（M2）

依赖：M1 通过，B 取件／授权、C 多门、D 背包／救援。

5. 验证任务 02／03 跨楼失败恢复、备用卡无权限、309 重复 E、闺蜜跨层和任务后检查点。

交付：1F→201→202→303→309 连贯流程。验收：不再用“已救援夹具”替代真实救援。

### A-V4-07 任务 04／05 与结局（M3）

依赖：M2、B 文件偷窃、C 后段门、D 后段 UI。

2. 5F 放前半段登记台、503 交付、EXIT，分别校验批准、交付和已救援。

### A-V4-08 整合回归与节奏调优（M4）

交付：可复测的候选版和剩余问题清单。验收：阻塞问题关闭，每个任务至少两人测时，全员各一次通关。

交付：经过目标系统验证的游戏和材料。A 本机能导出不等于其他电脑已运行。

## 5 B：员工、卡片与三种工作

### B-V4-01 扩展员工交互并补正面失败（M1）

依赖：A-V4-01 输入与可偷条件。

1. 在现有 `staff.tscn`／脚本加固定目标 ID、奖励类型与奖励 ID，第一步只用保洁卡。
2. 保留接近、朝向、背后站定和长按；区分条件不足的提示与“正面尝试偷窃”的任务失败。
3. 处理松键、移动、失去目标、开 UI 和任务失败时的取消；中途回头优先被抓。
4. 将 E 的开始／保持／释放接入 A 的唯一目标分发，避免每名员工各吃一次输入。
5. 成功后提交一次收集／进度事件；读持久状态决定“已取”，换楼不能重新给卡。

交付：可绑定主角、可配置奖励的员工与 F6。验收：背后成功、正面失败、回头失败、取消无奖励、同卡只给一次；现有行为修改同步测试预期。

### B-V4-02 CardManager 输入边界与快照（M1，M2 补齐装备体验）

依赖：A 的任务／模态状态约定。

1. 保留三卡所有权、两个槽、当前槽及查询副本；不为任务文件增第四卡。
2. 新增深拷贝导出／恢复接口，恢复验证合法卡与槽位，通知显示但不发主动 `identity_changed`。
3. Q 只在允许状态执行一次；失败、对白、加载、恢复期间不能通过 Autoload 偷换卡。
4. 装备按钮与 Q 共用业务入口；背包中的装备变更按核验快照规则通知 C，不能因暂停丢失事件。
5. 确认空槽、同卡移槽、卸下、重复选择、无效卡的玩家规则，写进接口；不要仅把当前偶然行为当成产品决定。

交付：查询／操作／快照与身份事件说明。验收：快照不随原数组变化、恢复准确且不误报警、第一二三卡入槽正确、无效操作不重复通知。

### B-V4-03 清理工作点（M1）

### B-V4-04 取包裹与批准（M2）

## 8 每次交付给 A 的固定格式

每个可运行组件先 F6 自测，再检查改动范围，由成员在自己的功能分支提交。PR 至少写：

1. 对应成员任务号、PLANS 编号、已完成／未完成范围。
2. 场景／脚本路径与 F6 启动入口，新增资源及 UID 是否齐全。
3. 公开配置、需要的主角／管理器接口、发出的信号；每个接口标记真实已实现。
4. A 在哪个楼层／Slot 放组件，调用 setup 的时机、需要连接的事件和初始刷新。
5. 运行过的成功／失败／边界用例、实际结果与日志／截图；没有做的人工或跨机器检查单列。
6. 文件归属、接口迁移影响、剩余风险；涉及别人模块时先说明最小必要变更。

A 接入后运行相关回归并记录进度，再按团队授权合入；别人同步同一个 main。当前长期分支继续使用，不因新版文档自动创建分支、提交、推送或合并。
